# reload、disable、回滚、`@<id>`

## 一条生命周期

插件就是 `.dock/plugins/<id>/`（或 `~/.dock/plugins/<id>/`）。没有「会话插件」，
没有要手动管的版本号：

```
写 / 改文件  →  cordis_plugin reload <id>  →  use_tool 验证  →  （再改 → 再 reload）
```

- 启动时、以及桌面 GUI 打开某个项目的会话时，目录里的插件自动装上。项目自带的插件
  第一次加载前（以及文件被别人改过之后）要用户点头；你 `reload` 过的那一版已经算点过头。
- `reload` 读的是**那一刻**的文件，拍成快照跑起来；之后改文件不影响正在跑的版本，
  再 reload 才换上。
- 项目级的根是**调用工具的那个会话**的工作目录。同 id 两层都有时项目级优先，
  回执会提醒另一份被盖住了；要操作用户级那份就传 `scope: "user"`。

## `reload` 做什么

1. 按 id 找目录，读 `plugin.toml`（可选）和 `source.rhai`。
2. 编译。编译不过：什么都不动，正在跑的那版照跑。
3. 已经在跑：先整个卸掉旧版（它登记的工具、斜杠、面板、钩子、bag 全撤），再起新版。
   不是叠加。
4. 新版起不来（apply 抛错、名字被占）：**自动回到上一版**继续跑，回执说
   「上一版仍在运行（已自动回滚）」，`cordis_inspect` 记着这次的错误，修好再 reload
   一次成功就清掉。
5. `plugin.toml` 写着 `enabled = false` 的，reload 顺手改成 true——reload 就是启用。

回执的 `登记：` 一行是这一版实际挂上的东西，`下一步：` 一行告诉你怎么验证或修。

## 权限

- `reload` / `disable` 走和 `bash` 一样的确认。确认框里写着插件目录、它挂的钩子、
  声明的 HTTP host。
- 用户选「始终允许」是**按插件和它挂的钩子 / 声明的 HTTP host** 记的：只改代码迭代不用
  每次点；多挂一个钩子、多声明一个 host 会再问一次；换一个插件还会问。
- 用户拒了：除非用户再要求，不要重新申请。
- 计划模式里两个动作都被挡。

## `disable`

停掉、`plugin.toml` 写 `enabled = false`（下次启动不装），文件都留着。要删目录先问用户。

## 副作用归谁

- 每个 `provide` / `register_*` / `host.on` 归**这次运行**；reload 换版或 disable 就
  一起撤掉。没有 `unregister_*`。
- apply 抛错：已登记的那一半先挂上，宿主在报错返回之前全部卸掉，不会泄漏。

## 用户写了 `@<id>`

系统提醒里有那个插件的目录、名字、状态（没有源码）。改它就改那个目录的文件，再
reload。目录不在了就直说，不要造一个同名的替身。
