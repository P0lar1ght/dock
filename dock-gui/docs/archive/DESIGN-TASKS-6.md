# Dock GUI 设计任务 · 第六轮：Pull Request 与定时任务（给 Grok Bot · UI 设计助手）

通用要求同 `DESIGN-TASKS.md`（取值、字号、按钮、文案用中文、不画动效只写注释）。
外壳照 `his`（Page - Dock Shell Light Glass），**不要重画外壳**：
- 侧栏原样；导航里对应那一项是选中态（「Pull Request」或「定时任务」）。
- 右侧不是对话：整块内容区换成本页内容，没有输入框、没有右侧工具面板。
- 内容区顶部是页头（标题 + 副标题 + 右侧按钮），下面是正文，可滚动。
每张画板尺寸和 `his` 一样（整窗）。
放置：先 get_artboards 看占用，新开一列空白，不压已有画板；间隔 60。
画板 label 英文：`Page PR <状态>`、`Page Schedules <状态>`。
画完导出 png + jsx（get_element_code）到 `dock-gui/wonder-ui/pages/<画板名>/`，
每个目录 README 写 node id。

## 0. 两页共用

- 页头：
  - 左：标题（20px 半粗）+ 灰色副标题一行；
  - 右：次按钮 +（可选）主按钮。
- 列表行、胶囊、空状态的样式和设置页（`reis` 系列）一致。
- 时间一律相对时间：「3 分钟前」「明天 09:00」，悬停显示完整时间。
- 不要写 Dock 给不了的数（例如 PR 的评论内容、CI 日志）。

## 1. Pull Request（数据来自本机 `gh`）

### 1.1 `Page PR List`

- 页头：
  - 标题「Pull Request」；
  - 副标题「经本机 gh 读取，只读」；
  - 右侧：项目下拉（显示项目名 dock，下拉里列「预设 · 项目」树里的项目）+「刷新」次按钮。
- 项目下拉下面一行灰字：仓库 `P0lar1ght/dock` · 我是 `P0lar1ght`。
- 三个分组（分组标题 + 数字）：
  - 「请我 review」；
  - 「我的」；
  - 「其他」。
- 每行（高 56 左右）：
  - 左：`#172` 等宽灰字 + 标题（一行截断）；
  - 第二行小字：作者 · `feat/durable-schedules → main` · 更新于 2 小时前；
  - 右侧胶囊组：
    - CI 状态：绿「检查通过」/ 红「2 项失败」/ 黄「进行中」/ 灰「无检查」；
    - review：「已批准」/「需要修改」/「待 review」（没有就不画）；
    - 草稿 PR 加灰色「草稿」胶囊；
  - 悬停出现两个图标按钮：「在浏览器打开」「让 Agent review」。
- 示例数据（照画）：
  - 请我 review：#168 feat(gateway): 设置页写配置…（bob · 待 review · 进行中）；
  - 我的：#172 定时任务落盘…（检查通过 · 可合并）；#173 vcs/pr/list…（草稿 · 无检查）。
  - 其他：#160 fix(tui): …（2 项失败 · 需要修改）。

### 1.2 `Page PR Detail`

- 点一行，右侧滑出详情抽屉（宽 440，盖在列表上，左边列表变暗一点）：
  - 头：`#172` + 标题（可两行）+ 右上角关闭；
  - 一行胶囊：状态（开放 / 草稿）· 可合并 / 有冲突 / 被阻塞 · review 结论；
  - 分支行：`feat/durable-schedules` → `main`；
  - 改动量：`+1368 −156 · 22 个文件 · 4 条评论`；
  - 「检查」小节：每项一行（状态图标 + 名字 + 右侧「查看」链接）；
  - 「Review」小节：每人一行（头像首字 + 名字 + 结论胶囊 + 时间）；
  - 「描述」小节：PR 正文，markdown 渲染，最多显示 12 行，「展开」；
  - 底部固定两个按钮：
    - 主按钮「让 Agent review」（新开一个会话去 review，用编码预设）；
    - 次按钮「在浏览器打开」。

### 1.3 空状态（四张小画板，只画内容区就行）

同一个居中卡片样式：图标 + 一句标题 + 一句说明 + 一个按钮。
- `Page PR No Gh`：没装 gh。
  - 标题「没找到 GitHub CLI」；
  - 说明「Pull Request 页靠本机的 gh 读取。安装后登录一次即可。」；
  - 代码块两行：`brew install gh` / `gh auth login`，各带复制按钮；
  - 按钮「重新检测」。
- `Page PR Unauthenticated`：gh 没登录。
  - 标题「gh 还没登录 GitHub」；代码块 `gh auth login`；按钮「重新检测」。
- `Page PR Not GitHub`：项目没有 GitHub 远端 / 不是 git 仓库。
  - 标题「这个项目没有 GitHub 远端」；说明里列项目路径；按钮「换个项目」。
- `Page PR Empty`：一切正常但没有开着的 PR。
  - 标题「没有开着的 Pull Request」；按钮「在浏览器打开仓库」。
- 另画加载态：三行骨架屏（`Page PR Loading`）。
- 另画出错条：列表上方红色细条「gh 执行失败：HTTP 502」+「重试」。

## 2. 定时任务

任务属于某个会话，按间隔把一句提问发进那个会话；Dock 重启后继续跑，7 天后过期。
到点时会话关着，会在后台打开再发。

### 2.1 `Page Schedules List`

- 页头：
  - 标题「定时任务」；
  - 副标题「按间隔向会话发送提问 · 保存在 ~/.dock/schedules.json」；
  - 右侧主按钮「+ 新建定时任务」。
- 按会话分组：分组标题 = 会话标题 + 项目名小字 + 右侧「打开会话」链接。
- 每个任务一行：
  - 左：时钟图标 + 提问（一行截断，悬停看全文）；
  - 第二行小字：「每 10 分钟」· 下次 3 分钟后 · 7 天后过期（剩不到 1 天时这段变橙色）；
  - 右侧：上次运行时间（「上次 7 分钟前」）；
  - 悬停出现「编辑」「删除」图标按钮。
- 两种特殊行：
  - 上次没送到：行下方加一条浅红提示「上次没发出去：会话打不开（已删除？）」；
  - 由另一个 Dock 进程负责：右侧灰色胶囊「由其他窗口运行」，悬停说明
    「另一个 Dock 进程持有它；那个进程退出后，这里会接管」。
- 示例数据（照画）：
  - 会话「review代码并提交pr」（dock）：
    - 「检查 CI 是否全绿，有失败就总结原因」· 每 30 分钟；
    - 「看一下 main 有没有新提交需要 rebase」· 每 2 小时 · 上次没发出去。
  - 会话「打开浏览器，搜下哔哩哔哩最近…」（dock）：
    - 「刷新排行榜并更新画布」· 每 1 天 · 由其他窗口运行。

### 2.2 `Page Schedules New`（弹窗，盖在列表上）

- 标题「新建定时任务」。
- 字段：
  - 「发到哪个会话」：会话下拉（按项目分组，带搜索）；
  - 「间隔」：数字输入 + 单位下拉（分钟 / 小时 / 天）；最短 1 分钟，下面灰字提示；
  - 「提问」：多行输入，占位「每次到点发给 Agent 的话」；
  - 复选「创建后立即运行一次」。
- 底部说明灰字：「7 天后自动过期。Dock 没开着的时候不运行，错过的不补。」
- 按钮：「取消」/「创建」（提问为空时禁用）。
- 另画 `Page Schedules Edit`：同一个弹窗，标题「编辑定时任务」，
  会话字段只读显示，按钮「保存」，左下角红字「删除」。

### 2.3 空状态与确认

- `Page Schedules Empty`：
  - 图标 + 「还没有定时任务」；
  - 说明「在对话里输入 /loop 10m 检查 CI，或点下面的按钮」；
  - 主按钮「+ 新建定时任务」。
- `Page Schedules Delete Confirm`：小确认框
  「删除这个定时任务？」+ 提问原文（灰）+「取消」/「删除」（红）。
